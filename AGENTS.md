# Bridgeplay

Bridgeplay runs Windows-only Steam games on Apple Silicon Macs inside the native macOS Steam
client. It turns on Steam Play in Mac Steam and runs games through CodeWeavers' WineCX with
Apple's Game Porting Toolkit (D3DMetal), DXMT or DXVK. It is a GPL-3.0 fork of
[NotProton](https://github.com/NotProtonNot/NotProton). User overview: [README.md](README.md).

## Stack

- `app/`: SwiftUI app, CLI and native installer (SwiftPM, Sparkle). See [app/AGENTS.md](app/AGENTS.md).
- `dylib/`: `notproton.dylib` in C, injected into Steam, plus the POSIX `sh` run script that
  launches every game. See [dylib/AGENTS.md](dylib/AGENTS.md).
- Wine side: Proton's lsteamclient and `steam.exe`, ntdll detours
  ([ntdll-patch/AGENTS.md](ntdll-patch/AGENTS.md)), patched Wine files and small Windows DLLs
  built with mingw-w64, committed as prebuilt binaries in `app/Sources/BridgeplayApp/Resources/`.
- Python and shell for build scripts and tests.

The full folder map is in [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

## Build and test

A full build needs an Apple Silicon Mac with Xcode 27 ([docs/BUILD-LOCAL.md](docs/BUILD-LOCAL.md)).

```sh
scripts/build-local.sh            # full build in CI order (output: build/Bridgeplay.app)
scripts/build-local.sh --checks   # the same, then make ci-checks
make ci-checks                    # every check the app workflow runs (CI_CHECKS in the Makefile)
make scriptcheck runcheck         # the lint workflow; works on Linux with shellcheck 0.11.0
make <target>                     # one check; make tests-list prints the test folders
make deploy                       # after make fonts: copy the dylib into Steam.app and install support files
```

A check whose tool or input is missing prints `skipped` and exits 0: that is not a pass.
Install the tool, or say the check didn't run. `make deploy`, and launching a built app,
change the real Steam and engines on this Mac (see [docs/DEVELOPING.md](docs/DEVELOPING.md)).

## Hard rules

- **Users' data:** never lose a game's save or prefix data. Don't rewrite `Steam.app` or
  Steam's config files while Steam is running (Steam rewrites `config.vdf` when it quits).
- **Design for the real setups:** several Steam accounts on one Mac, several Steam library
  folders (external drives too), several macOS users sharing one `/Applications/Steam.app`,
  and volumes that are case-sensitive or not APFS.
- **Legacy names stay:** existing installs depend on `notproton.dylib`, the `NOTPROTON_*`
  variables, `com.notproton.*` identifiers and the fallback to the old `notproton` support
  folders. Don't rename them. User-facing names are Bridgeplay's (`BRIDGEPLAY_*`).
- **Shipped binaries:** a Wine patch or shim change is not finished until its binary is rebuilt
  with the recipe in its folder's README or [docs/WINECX.md](docs/WINECX.md), and its sha256 is
  updated in `docs/WINECX.md`, `app/Sources/BridgeplayApp/Model/FreeEngineWinecx.swift` (or
  `FreeEngine.swift`), `app/Sources/BridgeplayApp/Support/SignedPin.swift` for a `.so` or
  `.dylib`, and [NOTICE](NOTICE). Don't commit a binary without its source.
- **Credit and licence:** contributions are GPL-3.0 unless the files carry another licence
  ([NOTICE](NOTICE)). Code from someone else keeps its author (`git cherry-pick -x`, or a
  `Co-authored-by:` line naming the source); new third-party code goes in NOTICE.
- **Upstream:** changes that belong upstream go to NotProton. Port an upstream PR only after
  it is merged there.
- **Large changes:** open an issue first, and check closed issues and PRs for duplicate work.
- **Localization:** user-facing app strings are localized (en, it, ru, zh-Hans); `make l10ncheck`.
- **Versions:** bumps are separate `chore(release)` commits made with `scripts/bump-version.sh`.
- **Commits:** Conventional Commits, e.g. `feat(setup): …`, `fix(migration): …`, `docs: …`.
- **PRs:** fill every section of [.github/pull_request_template.md](.github/pull_request_template.md)
  with the checks actually run and what wasn't tested. Run the checks your change touches first.
- **Comments:** short, and only where the code is hard to follow.
- **Replies:** replies to people in issues, PRs and discussions are written by a human.
