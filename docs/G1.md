# Gate G1: the beta update channel's acceptance run

G1 must be green before the first release that carries the beta code (`S_support`). It has two
halves: script fixtures (one command) and a run on a real Sparkle client against local feeds
(this sheet). The escape rehearsal is added when T8 lands.

## Fixtures

```sh
SPARKLE_BIN=app/.build/artifacts/sparkle/Sparkle/bin make -s g1check
```

Runs `ledgercheck`, `stablecheck`, `betacheck`, `versioncheck`, `cicheck` and
`native-installercheck`, and fails if any of them fails or prints a skip line. The suites name
R1 (ledgercheck, betacheck), R4 (stablecheck), R6 (betacheck), I-6 (stablecheck), X-15 and X-16
(betacheck) and X-18 (stablecheck). X-14 and X-17 carry no label in the suites; confirm which
cases they are before signing G1 off.

## The kit

`scripts/g1-kit.sh` builds test clients, writes feeds and serves them. It never uses the
release key, the keychain, `/Applications`, Steam or the real `com.bridgeplay.Bridgeplay`:

- the key is a throwaway made in the kit folder (`out/g1-kit`, or `G1_KIT`); its public half goes
  into the test bundles only;
- the test client is `dev.bridgeplay.g1kit`, installed at `out/g1-kit/Applications`. Its
  executable is a wrapper that sets `CFFIXED_USER_HOME` to `~/.bridgeplay-g1kit`, so its support
  folder, `app.log`, `bridgeplay.log` and caches live there. Its defaults are its own domain in
  `~/Library/Preferences`;
- `reset` points `steamAppPath` at a missing Steam.app, pauses the Steam patch keeper, marks the
  setup assistant done and sets `BetaFeedURLOverride` to the local beta feed;
- the feeds are served on `127.0.0.1:8765` (`G1_PORT`) over HTTP, which Sparkle accepts because
  the client has an EdDSA key; every request is logged to `out/g1-kit/server.log`, so a row can
  show which feed was read.

Test builds are stamped from one Swift build: stable 80, 83 and 86 are `0.8.<build>`, betas 82
and 84 are `0.8.<build>-beta.1`. The old client is 0.7.63 (80), built from its tag.

```sh
sh scripts/g1-kit.sh serve              # in a second Terminal; leave it running
sh scripts/g1-kit.sh scenario X-2       # builds what the row needs, resets, installs the start build
sh scripts/g1-kit.sh launch             # quit | kill | status | defaults ... | help
sh scripts/g1-kit.sh clean              # afterwards: the client's defaults, sandbox and caches
```

`status` prints the installed build, the beta defaults, the last update-check lines and the
last requests served. Sparkle checks at launch only when the last check is older than an hour:
to make the next launch check, run `sh scripts/g1-kit.sh defaults delete SULastCheckTime` before
launching, or use Check for Updates… in the Bridgeplay menu. The beta switch is on the Status
page's Updates section (`BetaUpdatesUI` is set by the scenarios that need it).

## Run sheet

For each row: run the scenario, launch, do the action, then record the update-check line
(`status`), the requests served, the build after quit and relaunch, and what the UI showed. A row
is green when every expected item holds.

| Row | Scenario | Action | Expected |
|---|---|---|---|
| Beta off | `beta-off` | Launch; quit once 83 has downloaded; launch | Only `/stable.xml` is requested, never `/beta.xml`. Log `state=stable`, the stable feed, no notes. 83 installs on quit and runs after relaunch. The Status page has no Updates section |
| X-1 | `X-1` | Launch | Offered 83 only; `/beta.xml` never requested |
| X-2 | `X-2` | Turn on Get beta updates and confirm; quit once 82 has downloaded; launch | A check reads `/beta.xml` (`state=beta`) and chooses 82; after relaunch the label is 0.8.82-beta.1 and Status shows beta updates on |
| X-3 | `X-3` | Launch, Check for Updates… | `state=beta`, `chosen=none`, note `stable 83 does not contain 82`; 83 not downloaded |
| X-4 | `X-4` | Launch | Chooses 84 (beta-critical) |
| X-5 | `X-5`, then `X-5c` | Turn the switch off and confirm; Check for Updates… | `state=leaving`. With beta 84 (`X-5`): not offered. With beta-critical 84 (`X-5c`): offered 84 |
| X-6 | `X-6` | Launch; quit once 86 has downloaded; launch | `state=leaving` chooses 86 (lists 82); after relaunch `state=stable` and the one-time back-on-stable row shows once, not on the next launch |
| X-8 | `X-8`, with `serve --slow 60` | Turn the switch on and confirm, then off and confirm before the zip finishes (watch `server.log`); quit; launch | The next check reads `/stable.xml`; no beta is installed after relaunch (still 0.8.80) |
| R2 pending | `R2-pending` | Launch; once 84 is waiting for quit, turn the switch off. Record what the dialog predicts. Confirm, quit, launch | Record predicted build and state against the result. Expected: 84 installs (Sparkle can't cancel it), then `state=leaving` |
| R2 resumable | `R2-resumable` (automatic install off) | Launch; install 84 from the update prompt and choose to install later, so it stays downloaded; turn the switch off; Check for Updates… | Record the dialog's prediction against the result. The log shows the update resumed with `which the leaving state does not allow; Sparkle installs it anyway` |
| R2 opt-in while stable pending | `R2-optin` | Launch; once 83 is waiting for quit, turn the switch on. Record what the dialog predicts. Confirm, quit, launch; Check for Updates… | Record the prediction. Expected: 83 installs first, then `state=beta`; the next check offers 84 |

| Old client and Setup, signed stable feed | `old-client` | Launch 0.7.63; quit once 83 has downloaded. Then `sh scripts/g1-kit.sh setup-parse` and `setup-parse v0.7.63` | 0.7.63 updates to 83 from the signed feed with `containsBetas`. Both parsers print `setup parsed: 0.8.83 (83), macOS 26.0` |
| X-11 | two macOS accounts, kit in `/Users/Shared` | See below | Account B launches in `state=leaving` with the "another account" message and is never downgraded |
| Escape rehearsal | — | Not run: T8 is held. Added when T8 lands | — |

**X-11.** In account A: `G1_KIT=/Users/Shared/bridgeplay-g1 sh scripts/g1-kit.sh scenario X-2`,
then `chmod -R a+rwX /Users/Shared/bridgeplay-g1`. In account B (from a checkout or a copy of the
script, same `G1_KIT`), with the client quit in A: `sh scripts/g1-kit.sh reset`. In A, run X-2 to the end (82 installed).
In B, launch: the update line says `state=leaving running=82 (beta)`, Status shows the other
account's beta, and no stable below 82 is installed.

Notes from the sample run:

- An update that is waiting for quit installs even when the app is killed (`kill -9`), so
  `R2-resumable` turns automatic install off.
